magicpin Vera Bot

A deterministic Spring Boot API with optional, bounded Gemini message enrichment. The decision and every factual claim remain grounded in supplied context.

Evaluator / client

HTTP + JSON requests. A deployment platform routes health probes to /v1/healthz.

InMemoryStore

Collision-safe context keys, latest decisions, and per-conversation state. Designed for one evaluator instance.

Replica boundary: context and conversations are intentionally in memory. They reset on restart and are not shared across replicas; use one replica for challenge evaluation.
HTTP surface

GET /v1/healthz

Returns liveness, uptime, and loaded-context count. Use for platform health checks.

GET /v1/metadata

Returns bot identity, version, model strategy, and deterministic approach.

POST /v1/context

Validates non-empty scope and context_id, then replaces that exact context.

POST /v1/tick

Accepts available_triggers or active_trigger_ids, scores per merchant, then returns Vera actions.

POST /v1/reply

Processes STOP, auto-replies, role flows, and terminal states with per-conversation synchronization.

Action contract

Actions include grounded merchant_id, rationale, CTA, send_as: vera, and a stable suppression key.

Decision path

  • Context is loaded by exact scope + ID.
  • Merchant-specific triggers cannot leak across merchants.
  • Deterministic category messaging is generated first.
  • Selection never records execution.

Optional Gemini path

  • Disabled unless GEMINI_ENABLED=true.
  • API key arrives only through environment/secret injection.
  • 8-second bounded timeout by default.
  • Malformed or ungrounded output falls back safely.

Container runtime

  • Multi-stage Maven build runs tests.
  • JRE-only non-root final image.
  • PORT and Gemini settings are runtime environment variables.
  • Use /v1/healthz for readiness/liveness probes.
